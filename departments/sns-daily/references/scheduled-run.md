# ルーティン: 毎朝の SNS 投稿案（定期実行用の手順書）

定期実行のプロンプトには、次の一文だけを書く（`<アプリID>` は `growth.mjs app list` の ID）。

```
SNSの投稿案を作る。~/.claude/skills/sns-daily/references/scheduled-run.md を読み、アプリID <アプリID> でそのとおりに実行する。
```

---

`sns-daily` スキルの手順（SKILL.md）に従い、指定されたアプリの今日の SNS 投稿案を作ります。ユーザーは不在なので質問はせず、足りない情報があれば報告して終えます。

## 読むもの（必ず）

- アプリの前提: `departments/marketing/apps/<アプリID>.md`
  - まず `growth.mjs app list` で stage（公開前・公開後）を確認する。
  - 「SNSアカウントとチャネル」に、使う SNS・回数・今の SNS 計画のファイルが書いてある。
- 決まり: `departments/marketing/RULES.md`
- 今の SNS 計画: アプリの前提に書かれたファイル（例 `campaigns/<キャンペーン>/sns-plan.md`）
- プロジェクトの予定: `departments/pm/projects/<アプリID>.md`（`pm list <アプリID>`）
- 直近の投稿案: `departments/marketing/content/`（同じネタ・同じお題をくり返さない）

## 守ること

- **他社のアプリ名・サービス名を使わない**。たとえ（〇〇版・〇〇風）やハッシュタグとしても使わない。
- **音楽は商用利用できるものだけ**。依頼投稿は PR 表記。人の写真を紹介するときは、本人の許可を取る前提で書く。
- **事実を確かめる**。「審査に出した」「直した」「公開した」「実装した」は、マイルストーンが完了（[x]）のときだけ書く。未実装の画面は「開発中の画面」と入れる案にする。公開日はマイルストーンを正とする。
- **アカウントの有無**: まだ無いチャネル（「アカウントを作る」のマイルストーンが未完了など）の案は「アカウントを作ったら使うストック」と明記する。今日出せるチャネルの案を、必ず1本入れる。
- 曜日ごとの回数（例: リールは月・水・金だけ）が計画にあれば、それに従う。作りすぎない。
- 架空の体験談・根拠のない表現は書かない。

## 出力

- `departments/marketing/content/YYYY-MM-DD-sns.md` に保存する（`sns-daily` の形式）。
  - 各案に3行を足す: 「**今日投稿できるか**: できる／アカウント作成後」「**用意するもの**: 素材・撮る画面」「**時間の目安**: ◯分」
- TODO を入れる。前の日の同じ TODO はためずに置き換える。

```
node "$HOME/.claude/skills/secretary/scripts/secretary.mjs" todo add "SNS投稿: <アプリ名>（案: content/YYYY-MM-DD-sns.md）" --replace "SNS投稿: <アプリ名>"
```

- 最後に、日本語でくわしく報告する。
  - 案ごとに: チャネル、フック、どんな投稿か（2〜3行）、用意するもの、時間の目安、今日投稿できるか、気をつけること
  - 最後に「投稿したら教えてください。数字（参加人数なども）を記録して計測します」と添える。
